# Agent Team 全流程协作模式

用户通过 `/team` 命令触发了团队协作模式。你必须按以下流水线严格执行，不能跳过任何阶段。

## 流水线阶段

### 阶段 1: 产品分析 (Product Manager)
调用 `product-manager` agent，要求它：
- 分析用户需求，明确功能范围
- 拆解为具体的前后端任务
- 输出简要 PRD（背景、流程、验收标准）

将 PM 的分析结果展示给用户，确认后再进入下一阶段。

### 阶段 2: 技术方案
基于 PM 的需求分析，你作为架构师：
- 确定涉及哪些文件需要新增/修改
- 设计数据流和接口契约
- 判断前后端任务是否可以并行

将技术方案展示给用户，确认后再进入下一阶段。

### 阶段 3: 开发实现
根据任务类型调用对应 agent：
- **仅前端**: 调用 `frontend-dev`
- **仅后端**: 调用 `backend-dev`
- **前后端都涉及**: **并行**调用 `frontend-dev` 和 `backend-dev`

如果新增了后端 API，必须同步更新 `vite.config.js` 的 proxy 配置。

### 阶段 4: 测试验证
调用 `tester` agent：
- 根据 PRD 的验收标准设计测试用例
- 执行测试并输出测试报告
- 发现问题直接修复，修复后重新验证

### 阶段 5: 代码审查
调用 `code-reviewer` agent：
- 审查本次所有变更的代码
- 按 🔴 Critical / 🟡 Warning / 🟢 Suggestion 分级
- Critical 和 Warning 级别问题必须修复

### 阶段 6: 总结报告
输出最终报告：
```markdown
## Team 协作报告

### 需求
[一句话描述]

### 完成的工作
- [变更列表]

### 测试结果
- ✅/❌ [测试概要]

### 审查结果
- [关键发现]

### 涉及文件
- [文件列表]
```

## 重要规则

1. **每个阶段完成后向用户汇报进度**，关键决策点需要用户确认
2. **不要跳过阶段**，即使任务看起来很简单
3. **发现问题立即修复**，不要留到后面
4. **保持阶段间的信息传递**，后一个 agent 需要知道前一个 agent 的产出
